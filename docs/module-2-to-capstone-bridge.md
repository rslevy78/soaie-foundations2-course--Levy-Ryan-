# Module 2 to Capstone Bridge

This note keeps continuity meaningful without turning the Module 2 source repo into a full multi-module content pack.

## Reuse from Module 2 in Module 5

- Meeting-summary pattern: use the same summarize -> identify change -> update artifact loop as a capstone build pattern.
- Backlog traceability: carry forward the habit of explicit acceptance criteria and review comments.
- Git discipline: keep branch/commit/PR review flow in capstone work, even for solo builds.

## Suggested facilitator prompt to learners

Use your Module 2 artifact style as your capstone starting pattern:
1. Define the change or problem clearly.
2. Draft a lightweight spec in plain language.
3. Build the smallest working version.
4. Validate output against real or staged data.
5. Commit and open a PR with a short rationale.
